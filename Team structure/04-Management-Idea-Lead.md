# Management & Idea Lead — Product & Vision Lead

← back to [[00-Atelier-Team-Structure-MOC]] · synthesizes input from [[01-RnD-Lead]], [[02-Technical-Lead]], [[03-Support-Moderation-Lead]]

## Mission

Own the question *"does this cohere into one product a newcomer can understand?"* — hold the whole map, make the final call when the other three roles disagree, and keep the project moving through phases as validation gates rather than stalling in endless research or endless polish.

## Primary phase ownership

**Phase 0 — Framework Integration (Primary)**
- Define the five spaces as canonical product entities with stable identities — this is a product decision (what is Discussion, definitively, and how is it definitively not Critique) before it's a technical one.
- Own the shared structural contract template (the 10-part blueprint) and make sure every space's framework doc actually uses it, so R&D's space-behavior work in Phase 1 has a consistent shape to build from.

**Phase 2 — Supporting Systems (Primary, shared with Technical & Moderation)**
- Own the *purpose* statements for onboarding, profile, dashboard, and creation flow — what each one is trying to accomplish for a beginner — before Technical builds them and Moderation adds checkpoints.
- Make the call on how much of the platform a first-time user sees vs. how much stays hidden until later (the progressive disclosure spine).

**Phase 3 — Cross-Space Coherence (Primary, shared with R&D)**
- Own the "no user guesswork" exit criterion — review every transition R&D designs and ask specifically whether a beginner would understand *why* this handoff is happening, not just that it works.
- Resolve naming and conceptual collisions between spaces (e.g. the "Case Study" collision between Critique's archive entries and Resource's field notes) before they reach implementation.

## Secondary / consulted

- **Phase 1:** sign off on build order and validation-gate criteria — is Discussion actually working end-to-end before Critique starts, per the strategy's own discipline.
- **Phase 4:** own progression thresholds as product decisions (what does "Contributor" actually mean to a newcomer looking at the ladder) while Moderation owns the anti-gaming enforcement underneath them.
- **Phase 5/6:** sign off that the info hierarchy and disclosure maps genuinely read as beginner-first before UI work locks them in.

## Whiteboard research question owned

**"How to structure UI/UX according to the idea?"** — this is explicitly a product-framing question before a design one: what does "structured, not generic-forum" actually look like on screen? Work this with Technical for feasibility, but you own the answer to *why* it should look that way.

## Immediate next actions

1. Finalize the canonical five-space definitions as short, stable one-paragraph statements each — this single artifact is what every other role's Phase 1+ work depends on staying consistent with.
2. Set the validation-gate criteria for "Discussion is done" in writing, before Technical starts building it, so there's an agreed answer to "are we ready to move to Critique" instead of a judgment call made under deadline pressure.
3. Start a `Decision Log` (see [[00-Atelier-Team-Structure-MOC]]) and seed it with every open question already resolved across prior analysis, so nothing gets re-litigated from scratch.
