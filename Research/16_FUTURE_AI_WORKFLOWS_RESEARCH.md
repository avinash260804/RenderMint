# Atelier Future AI Workflows Research

# Research Document Context

These files are created for **Atelier / Designers Hub**, a creative-professional community platform being reworked around forum discussions, structured critique, help posts, resources, profiles, dashboards, uploads, search, reputation, settings, moderation, and future admin systems.

The purpose of these files is not to provide final answers yet. Each file clearly defines **what data must be researched**, **why it matters**, **what questions to answer**, and **what output should be produced** before implementation decisions are made.

Use these files as research briefs for ChatGPT, Codex, manual web research, competitor analysis, product planning, and implementation planning.


## Purpose

This research explores future AI/agent systems for Atelier, but clearly separates them from the current rework. These ideas should not distract from core UI, community, security, and launch readiness.

## Main research objective

Research future AI workflows that could help critique, moderation, content quality, notifications, summaries, and community operations after the core platform is stable.

## Important rule

Do not implement heavy AI/agent infrastructure during the current rework unless it directly supports a launch-critical need. Store these ideas for later.

## Data to research

### 1. AI-assisted critique later

Research:

- AI critique suggestions.
- Critique quality prompts.
- Feedback category suggestions.
- Image understanding limitations.
- Human-in-the-loop critique.
- Avoiding generic AI feedback.

Data to collect:

- What AI can help with.
- What AI should not replace.
- How to keep human critique central.
- How to disclose AI assistance.

### 2. AI-assisted moderation later

Research:

- Spam detection.
- Toxicity detection.
- Low-effort post detection.
- Duplicate post detection.
- Stolen work detection limitations.
- Report triage.

Data to collect:

- What can be automated safely.
- What needs human review.
- False positive risks.
- Moderator UI needs.

### 3. Content quality assistance

Research:

- Post quality scoring.
- Prompting users to add context.
- Rewriting vague questions.
- Suggesting critique fields.
- Suggesting tags/disciplines.
- Resource description improvement.

Data to collect:

- Which assistance improves quality.
- Which assistance feels intrusive.
- How to keep user voice intact.

### 4. Notification and digest workers

Research:

- Email digests.
- Weekly critique summary.
- Unanswered help posts.
- Replies to user posts.
- Recommended discussions.
- Discipline-specific digests.

Data to collect:

- Which events matter.
- What should be immediate vs digest.
- How preferences should work.
- What background jobs are needed.

### 5. Background job architecture

Research:

- Queues.
- Scheduled jobs.
- Serverless workers.
- Webhooks.
- Trigger-based workflows.
- Logs/traces.
- Retries.
- Failures.

Data to collect:

- What infrastructure is needed later.
- What can be done without introducing complexity now.
- When to consider systems like workers/queues/agent infrastructure.

### 6. AI safety and trust

Research:

- AI disclosure.
- Avoiding hallucinated critique.
- Avoiding harmful feedback.
- User control over AI suggestions.
- Privacy of uploaded work.
- Consent for AI processing.

Data to collect:

- What must be disclosed.
- What user permissions are needed.
- What data should not be sent to AI models.
