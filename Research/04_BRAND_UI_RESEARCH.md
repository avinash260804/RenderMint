# Atelier Brand UI Research

# Research Document Context

These files are created for **Atelier / Designers Hub**, a creative-professional community platform being reworked around forum discussions, structured critique, help posts, resources, profiles, dashboards, uploads, search, reputation, settings, moderation, and future admin systems.

The purpose of these files is not to provide final answers yet. Each file clearly defines **what data must be researched**, **why it matters**, **what questions to answer**, and **what output should be produced** before implementation decisions are made.

Use these files as research briefs for ChatGPT, Codex, manual web research, competitor analysis, product planning, and implementation planning.


## Purpose

This research defines the visual and interaction direction for the Brand UI rework. It should prevent the UI from becoming generic, cluttered, overly SaaS-like, or randomly animated.

## Main research objective

Research how Atelier should look, feel, move, and organize visual hierarchy as a premium creative-professional platform.

## Data to research

### 1. Visual identity direction

Research visual styles that could fit Atelier:

- Premium editorial.
- Futuristic but calm.
- Creative-professional.
- Studio-like.
- Minimal but not empty.
- Bold but not noisy.
- Structured but not corporate.
- Community-first but not social-media chaotic.

Collect examples of:

- Strong landing pages.
- Premium dashboards.
- Editorial layouts.
- Creative portfolios.
- Design community interfaces.
- High-quality forum layouts.
- Critique/work review pages.

For each example, note:

- What works.
- What does not fit Atelier.
- Typography style.
- Spacing system.
- Card design.
- Visual density.
- Motion style.
- Use of imagery.

### 2. Page-type visual rules

Research visual direction separately for each page type:

#### Landing/public pages

- More editorial.
- More spacious.
- Stronger brand statement.
- Clear value proposition.
- Community credibility.

#### Explore/forum feed

- Scannable.
- Clear post metadata.
- Compact but premium.
- Filters and post types visible.
- Avoid clutter.

#### Critique pages

- More visual focus.
- Larger image/work area.
- Structured feedback panel.
- Calm reading space.
- Version/revision support later.

#### Thread pages

- Strong title hierarchy.
- Author context.
- Clear comments.
- Voting/status visible but not distracting.

#### Profile pages

- Portfolio-aware.
- Shows identity, discipline, contributions, reputation, and work.
- Should feel like a professional creative presence, not just account settings.

#### Dashboard

- Task-focused.
- Shows drafts, posts, replies, saved items, activity, recommended actions.
- Calm and useful.

#### Settings/admin

- Functional.
- Clear grouping.
- Accessible forms.
- Not visually overdesigned.

### 3. Typography research

Research typography direction:

- Display type for brand moments.
- Readable body type for long discussions.
- Code/technical text if needed.
- Metadata typography.
- Forum/card hierarchy.
- Critique readability.

Collect data on:

- Font pairings.
- Font size scale.
- Line height.
- Letter spacing.
- Heading hierarchy.
- Long-form readability.
- Mobile typography behavior.

### 4. Color and surface research

Research:

- Base background style.
- Light/dark mode possibility.
- Accent color usage.
- Neutral palette.
- Card surfaces.
- Borders and dividers.
- Status colors for solved/open/revised/featured.
- Safe use of gradients.
- Avoiding color noise.

Data to collect:

- What colors should be brand-defining?
- What colors should be functional only?
- How to show post type without clutter?
- How to make UI feel premium without overusing glassmorphism?

### 5. Layout and spacing research

Research:

- Page container widths.
- Grid systems.
- Sidebar usage.
- Feed/card spacing.
- Comment spacing.
- Profile layouts.
- Dashboard widgets.
- Empty states.
- Mobile stacking.

Collect examples of:

- Good dense layouts.
- Good spacious layouts.
- Bad cluttered layouts.
- Bad empty layouts.

### 6. Component research

Research components needed:

- App shell.
- Navigation.
- Mobile navigation.
- Post card.
- Critique card.
- Comment card.
- User card.
- Profile header.
- Discipline hub header.
- Filters/tabs.
- Create-post form.
- Upload component.
- Empty states.
- Dialogs.
- Dropdowns.
- Toasts.
- Admin tables.

For each component, research:

- Purpose.
- Variants.
- Data shown.
- States: default, hover, loading, empty, error, disabled.
- Mobile behavior.

### 7. Motion and microinteraction research

Research only meaningful motion:

- Post card hover.
- Comment reveal.
- Vote count change.
- Save/bookmark feedback.
- Tab switch.
- Create-post step transitions.
- Dropdown open/close.
- Upload progress.
- Notification badge later.

Avoid researching decorative motion that does not support usability.

### 8. Avoiding generic AI UI

Research what makes UI feel generic:

- Same card layouts everywhere.
- Too many gradients.
- Weak typography.
- No information hierarchy.
- Random icons.
- Overused rounded cards.
- Empty slogans.
- Poor spacing.
- Generic dashboard blocks.

Define what Atelier must avoid.

## Questions this research must answer

1. What should Atelier visually feel like?
2. What UI styles should be avoided?
3. How should forum pages differ from critique pages?
4. How should profile pages feel professional?
5. What component system is needed?

8. What should empty states look and say?
9. What design references are closest to Atelier?
10. What should Codex follow when reworking UI?
