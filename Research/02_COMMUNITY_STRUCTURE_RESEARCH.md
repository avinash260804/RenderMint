# Atelier Community Structure Research

# Research Document Context

These files are created for **Atelier / Designers Hub**, a creative-professional community platform being reworked around forum discussions, structured critique, help posts, resources, profiles, dashboards, uploads, search, reputation, settings, moderation, and future admin systems.

The purpose of these files is not to provide final answers yet. Each file clearly defines **what data must be researched**, **why it matters**, **what questions to answer**, and **what output should be produced** before implementation decisions are made.

Use these files as research briefs for ChatGPT, Codex, manual web research, competitor analysis, product planning, and implementation planning.


## Purpose

This research defines how Atelier should work as a community, not just as a collection of pages. It should help structure disciplines, post types, user roles, contribution behavior, moderation expectations, and quality standards.

## Main research objective

Research how strong online communities organize participation, maintain quality, welcome beginners, recognize experienced members, and prevent low-effort activity.

## Data to research

### 1. Types of community spaces

Research the difference between:

- General forums.
- Q&A communities.
- Critique communities.
- Portfolio communities.
- Professional networks.
- Learning communities.
- Private invite communities.
- Open public communities.

Collect data on:

- What kind of posts exist in each.
- What kind of moderation is needed.
- How users earn credibility.
- How new users are welcomed.
- What makes conversations useful.
- What causes community decay.

### 2. Atelier community zones

Research how these zones should behave:

- Public landing/community preview.
- Explore feed.
- Discipline hubs.
- Discussion threads.
- Critique threads.
- Help/Q&A posts.
- Resource posts.
- Showcase posts.
- Profiles.
- Dashboard.
- Settings.
- Admin/moderation.

For each zone, research:

- Purpose.
- User intent.
- Content types.
- Participation rules.
- UI density.
- Moderation needs.
- Quality signals.

### 3. Disciplines and categories

Research how design fields should be categorized.

Possible disciplines:

- Graphic design.
- UI/UX design.
- Product design.
- Brand identity.
- Motion design.
- Illustration.
- Typography.
- Web design.
- 3D design.
- Architecture/interior design if relevant.
- Photography if relevant.
- Creative coding if relevant.

Research:

- Should disciplines be broad or specific?
- Should users choose one primary discipline?
- Should posts belong to one discipline or many?
- Should critique expectations change by discipline?
- Should each discipline have its own hub page?
- What metadata is needed per discipline?

### 4. Post types and their rules

Research each post type separately:

#### Discussion

- What makes a good discussion?
- What context should be required?
- What should be discouraged?
- What sorting/filtering is useful?

#### Critique

- What project context is required?
- What type of feedback should be requested?
- How should comments be structured?
- How should revisions be handled?

#### Help/Q&A

- What makes a question answerable?
- How should accepted solutions work?
- Who can mark a solution?
- How should unanswered posts be surfaced?

#### Resource

- What qualifies as a resource?
- Should resources be reviewed or voted?
- Should external links be checked?
- How to prevent link spam?

#### Showcase

- Should showcase exist at launch or later?
- How is showcase different from critique?
- Should comments be praise-only, critique-allowed, or author-selected?

### 5. Community behavior and rituals

Research community rituals that create recurring participation:

- Weekly critique threads.
- Design challenges.
- Resource roundups.
- Beginner help sessions.
- Portfolio review days.
- Discipline-specific prompts.
- Featured member posts.
- Best critique of the week.
- Before/after improvement posts.

Collect data on:

- What rituals work in communities.
- What rituals fail.
- How much structure is needed.
- How to avoid forcing engagement.

### 6. Beginner and expert balance

Research how communities support both beginners and advanced users.

Data to collect:

- What beginners need to feel safe.
- What experts need to feel respected.
- How to avoid experts feeling used for free labor.
- How beginners can contribute before they are skilled.
- How mentorship can happen without overbuilding.
- How reputation can recognize quality feedback.

## Questions this research must answer

1. What should the main community spaces be?
2. Which post types should exist at launch?
3. Which post types should wait?
4. How should discipline hubs be structured?
5. What makes a post high quality?
6. What makes a comment useful?
7. How should Atelier prevent low-effort posts?
8. How should experienced users be recognized?
9. How should beginners be protected from harsh or useless criticism?
10. What community rituals should be introduced first?
