# Atelier Reputation and Rewards Research

# Research Document Context

These files are created for **Atelier / Designers Hub**, a creative-professional community platform being reworked around forum discussions, structured critique, help posts, resources, profiles, dashboards, uploads, search, reputation, settings, moderation, and future admin systems.

The purpose of these files is not to provide final answers yet. Each file clearly defines **what data must be researched**, **why it matters**, **what questions to answer**, and **what output should be produced** before implementation decisions are made.

Use these files as research briefs for ChatGPT, Codex, manual web research, competitor analysis, product planning, and implementation planning.


## Purpose

This research defines how Atelier should recognize valuable contributors without creating fake clout, popularity contests, vote manipulation, or unhealthy competition.

## Main research objective

Research reputation, badges, contribution scoring, expert recognition, beginner progression, and anti-gaming systems for a creative community.

## Data to research

### 1. Reputation goals

Research what reputation should accomplish:

- Recognize helpful contributors.
- Surface trusted critics.
- Encourage high-quality answers.
- Encourage thoughtful critique.
- Help beginners identify credible advice.
- Build professional identity.
- Reward consistency.
- Discourage spam.

Data to collect:

- What reputation should reward.
- What reputation should not reward.
- Whether reputation should unlock privileges.
- Whether reputation should be visible everywhere.
- Whether reputation should decay or stay permanent.

### 2. Actions that may earn reputation

Research possible reputation events:

- Upvoted post.
- Upvoted comment.
- Accepted solution.
- Helpful critique marked by author.
- Critique implemented by author.
- Resource saved/upvoted by others.
- Challenge participation.
- Featured post.
- Moderator-recognized contribution.

For each event, research:

- Should it give points?
- How many points?
- Can it be abused?
- Should there be daily caps?
- Should new accounts have restrictions?

### 3. Actions that should not earn reputation

Research actions that may create spam:

- Posting too frequently.
- Commenting without usefulness.
- Self-voting.
- Marking own answer as solution.
- Upvotes from suspicious alternate accounts.
- Low-quality resource links.
- Showcase likes only.

Data to collect:

- Which actions should have zero points.
- Which actions should have caps.
- Which actions should require quality validation.

### 4. Badges and recognition

Research badge categories:

- Helpful Critic.
- Strong Answerer.
- Resource Curator.
- Typography Specialist.
- Brand Identity Contributor.
- UI/UX Mentor.
- Early Member.
- Challenge Winner.
- Consistent Contributor.
- Portfolio Reviewer.

Data to collect:

- Which badges are meaningful.
- Which badges are gimmicky.
- Whether badges are automatic or manual.
- Whether discipline-specific badges should exist.

### 5. Expert recognition

Research how to recognize experienced users:

- Verified professional status later.
- Portfolio-linked credibility.
- Discipline expertise tags.
- Featured critic status.
- Moderator-curated recognition.
- Community-nominated experts.

Data to collect:

- How to avoid fake expertise.
- Whether manual verification is needed.
- Whether expert labels create hierarchy problems.

### 6. Beginner progression

Research how beginners can progress:

- First post milestone.
- First helpful comment.
- First critique request.
- First revision.
- Learning streaks.
- Improvement badges.
- Beginner-friendly prompts.

Data to collect:

- How to make beginners feel included.
- How to avoid intimidating them with expert rankings.
- How to reward learning behavior.

### 7. Anti-gaming systems

Research abuse cases:

- Self-voting.
- Alt-account voting.
- Vote rings.
- Mutual upvote groups.
- Fake accepted solutions.
- Spam commenting.
- Reputation farming.
- Low-quality critique farming.

Data to collect:

- What checks can exist at launch.
- What checks need scale later.
- What database constraints are needed.
- What rate limits are needed.

## Questions this research must answer

1. What should reputation mean in Atelier?
2. Which actions earn reputation?
3. Which actions should not earn reputation?
4. Should critique earn reputation?
5. Should accepted solutions earn more?
6. Should reputation unlock privileges?
7. What badges matter?
8. How are experts recognized?
9. How are beginners encouraged?
10. How is reputation abuse prevented?
