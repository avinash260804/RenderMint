Here’s a structured framework for the Resource Section using your headings, aligned with Atelier’s product principles.[^1]

## Purpose

- Provide a curated, contextual archive of discipline-specific resources that directly support discussions, critique, and project work.
- Help beginners and practitioners turn confusion into clarity by giving them “what to read/use next” at each stage of their design process.[^1]
- Become a living learning library for each Studio, not a generic tutorial dump or bookmark list.[^1]


## User types

- Beginners / students: Need guided, low-noise starting points, starter kits, and “how to use this resource” explanations.
- Early-career practitioners: Need process and standards references, case studies, and checklists that connect to real projects.
- Experienced creatives / mentors: Need a place to contribute field notes, curated collections, and endorse resources that shape Studio quality.[^1]
- Moderators / admins: Steward quality, approve or revise submissions, and maintain the archive’s structure.


## Entry states

Where users are coming from when they hit Resources:

- From Studio pages (exploring “Resources” tab for a discipline).
- From a discussion or critique thread (side panel suggestions: “Resources related to this topic”).
- From onboarding / beginner starter kits (e.g., “Start here: Graphic Design Studio starter resources”).
- From profile (viewing saved resources or ones they contributed, as part of their creative journey).[^1]

Each entry state should feel like a continuation of their current task, not a detour.

## First-time journey

For a completely new beginner:

1. They join a Studio (e.g., Architecture Studio).
2. On the Studio page, they see a “Beginner Starter Resources” block at the top.
3. Clicking it opens a focused subset of resources:
    - 3–7 items max.
    - Each with “What this is,” “Who this is for,” and “How to use this in your first project.”[^1]
4. As they ask a first question or critique request, the post-creation flow suggests 1–3 relevant resources based on tags and stage (“Before you post, this might help clarify your problem”).
5. When they return later, their profile shows “Resources I’ve saved / used,” reinforcing that the archive is part of their learning journey.[^1]

Goal: Within their first ten minutes, beginners understand that Resources help them ask better questions and improve work, not just collect links.[^1]

## Core components

- Studio Resource Archive:
    - Separate tab per Studio, with filters for Type, Level, Stage, and Tags.
- Beginner Starter Kits:
    - Curated bundles per Studio (“UI/UX Beginner Kit,” “Interior Design Basics”).[^1]
- Resource Cards:
    - Structured units with title, type, level, Studio, stage, short description, “why useful,” and usage hints.
- Personal Library:
    - Saved resources tied to profile, visible as part of creative identity and journey.[^1]
- Contribution Console:
    - Simple form to submit resources with required context fields and tags.


## Content types

Resource post types (kept small and clear):

- Handbook: Foundational, broad knowledge.
- Guide / Checklist: Step-by-step help for specific tasks (e.g., “Critique request checklist”).
- Standard / Reference: Codes, guidelines, rules, typographic or interface standards.
- Case Study / Field Note: Deep dives on real projects, process breakdowns, lessons learned.
- Starter Kit: Curated bundles for beginners (grouped resources for “first semester” feeling).[^1]

Each resource must explicitly answer:

- What is this?
- Who is it for (level)?
- Which Studio and stage does it belong to?
- What problem does it help solve and how should a beginner use it?[^1]


## Actions and permissions

**Members / Creatives:**

- Browse, search, and filter resources per Studio.
- Save resources to personal library.
- Submit new resources via structured form (with required fields and tags).
- Mark resources as “helpful,” comment with usage notes, and link them in discussions.

**Mentors / Experienced Creatives:**

- All member actions, plus:
- Curate Studio starter kits and thematic collections.
- Endorse resources (“Mentor pick,” “Recommended for beginners”).[^1]

**Moderators / Admins:**

- Approve or reject newly submitted resources.
- Mark resources as “Needs revision” and send feedback to contributors.
- Merge duplicates, retire outdated or low-quality items.
- Pin featured resources for each Studio.[^1]

Permissions can be tiered with reputation (e.g., only trusted contributors can create starter kits or endorse resources).

## Progressive disclosure layers

To keep it beginner-friendly and avoid overwhelming:

- Layer 1 (First-time / low complexity):
    - Starter kits only.
    - Simple filters: Beginner vs. All, Studio-only.
    - Usage hints on cards (“Use this before your first critique request”).
- Layer 2 (After some activity):
    - Full filters (Type, Level, Stage, Tags).
    - Ability to submit resources and save to personal library.
- Layer 3 (Experienced / high reputation):
    - Advanced actions: curate collections, endorse resources, propose Studio-specific resource guidelines.
    - Detailed moderation tools for contributors and mentors.[^1]

Access can be unlocked based on contribution (discussions, critiques, saved resources), consistent with progressive disclosure across Atelier.

## Moderation logic

Moderation should shape behavior, not just punish.[^1]

**Submission checks:**

- Required fields present: title, Studio, type, description, “why useful,” level, tags.
- Not obviously spam or self-promotion without learning value.
- Mapped correctly to Studio and stage (e.g., architecture codes not dumped in UI/UX).[^1]

**Quality states:**

- Draft / Pending review: visible to moderators only.
- Published: visible to Studio, may or may not have badges.
- Needs revision: visible but clearly marked; contributor prompted to improve context or tags.
- Deprecated / Retired: hidden from normal users, kept for internal reference if needed.[^1]

**Behavior shaping:**

- If a user submits low-context resources, the system nudges them with prompts (“Please explain how this helps someone in this Studio”).
- Prompts for mentors/moderators to add “How to use this” notes to raw references (e.g., standards, long PDFs).
- Report reasons specific to resources: “Outdated,” “Not relevant to Studio,” “Too advanced for labeled level,” “Low-quality explanation.”[^1]


## Success metrics

Measure success in terms of learning and usefulness, not volume.

**Usage \& relevance:**

- % of resource views coming from contextual suggestions (threads, starter kits) vs. direct archive visits.
- Click-through rate on recommended resources in discussions/critique pages.
- Saves per resource; ratio of “helpful” marks to total views.

**Impact on improvement:**

- % of solved discussions that link at least one resource.
- Increase in quality of posts (moderators and mentors report fewer “missing basics” problems over time).
- Before/after patterns: threads where the author used a resource and revised work vs. those that didn’t.

**Beginner comprehension:**

- Onboarding tests: time and steps for a beginner to find a relevant resource for a specific scenario.
- Short in-product surveys: “Did this resource help you with your current problem?”

**Community health:**

- Ratio of curated / endorsed resources to total resources (indicates curation, not dumping).
- Share of resources contributed by non-admins (community ownership).
- Drop-off or growth in low-quality submissions after “Needs revision” nudges and guidelines.[^1]

This framework should give you a clear product skeleton for the Resource Section that fits Atelier’s philosophy: beginner-first, structured, collaborative, and focused on long-term learning rather than link volume.
