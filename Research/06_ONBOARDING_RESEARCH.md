# Atelier Onboarding Research

# Research Document Context

These files are created for **Atelier / Designers Hub**, a creative-professional community platform being reworked around forum discussions, structured critique, help posts, resources, profiles, dashboards, uploads, search, reputation, settings, moderation, and future admin systems.

The purpose of these files is not to provide final answers yet. Each file clearly defines **what data must be researched**, **why it matters**, **what questions to answer**, and **what output should be produced** before implementation decisions are made.

Use these files as research briefs for ChatGPT, Codex, manual web research, competitor analysis, product planning, and implementation planning.


## Purpose

This research defines what happens when a user first joins Atelier. A community platform can fail if new users do not understand what to do, where to contribute, or why the space matters.

## Main research objective

Research how Atelier can guide first-time users into becoming meaningful participants instead of passive visitors.

## Data to research

### 1. First-time user goals

Research what different first-time users need:

- Beginner designer.
- Experienced designer.
- Student.
- Self-taught creator.
- User seeking critique.
- User seeking answers.
- User wanting to showcase.
- User browsing casually.

Collect data on:

- What they need to understand immediately.
- What information they are willing to provide.
- What first action feels natural.
- What causes confusion.
- What causes drop-off.

### 2. Signup and auth flow

Research:

- Google login.
- Magic link login.
- Email verification.
- Auth callback UX.
- Post-auth redirect.
- Returning user behavior.
- Error states.

Data to collect:

- What screen comes after login?
- How much onboarding is too much?
- Should users be allowed to skip?
- How should incomplete onboarding be handled?

### 3. Discipline selection

Research:

- Whether users should choose a primary discipline.
- Whether users can choose multiple interests.
- Whether discipline affects feed recommendations.
- Whether discipline appears on profile.
- Whether discipline affects critique templates.

Data to collect:

- Best UI for selecting disciplines.
- How many options to show.
- How to avoid overwhelming users.
- How to allow editing later.

### 4. Profile setup

Research required and optional profile fields.

Potential fields:

- Display name.
- Username.
- Avatar.
- Bio.
- Primary discipline.
- Skill level.
- Tools.
- Portfolio link.
- Location optional, but avoid collecting unnecessary personal data.
- Website/social links.

Research:

- What fields are needed at signup?
- What fields can wait?
- How to make profile creation feel valuable?
- How to avoid making signup feel like a form burden?

### 5. First action after onboarding

Research what first action should be suggested:

- Introduce yourself.
- Browse discipline hub.
- Ask for critique.
- Answer a beginner question.
- Save resources.
- Complete profile.
- Read community rules.
- Join a weekly challenge.

Data to collect:

- What first action creates retention?
- What first action creates community value?
- What first action is easy for beginners?
- What first action respects experts?

### 6. Empty-state onboarding

Research how to onboard users when the community is still small.

Data to collect:

- How to make empty pages useful.
- How to show starter posts.
- How to explain expected behavior.
- How to invite contribution.
- How to avoid making the platform feel dead.

### 7. Onboarding copy and tone

Research tone:

- Encouraging.
- Professional.
- Clear.
- Not childish.
- Not corporate.
- Not overhyped.

Collect examples of:

- Good onboarding copy.
- Bad onboarding copy.
- Empty state copy.
- Profile setup copy.
- First post prompts.

## Questions this research must answer

1. What is the ideal first 5 minutes after signup?
2. What data must be collected during onboarding?
3. What data should be optional?
4. Should onboarding be skippable?
5. How should users choose disciplines?
6. What first action should users be guided toward?
7. How should empty states educate users?
8. How should beginners and experts be onboarded differently?
9. What should onboarding avoid?
10. What is the minimum onboarding flow for launch?
